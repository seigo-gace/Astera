# Asteraの仕組み

Asteraは、入力された内容へすぐ結論を返すのではなく、いくつかの工程に分けて判断材料を作ります。

## 全体の流れ

```text
質問・相談・資料・AI回答
  ↓
内容を整える
  ↓
何についての問題かを分類する
  ↓
事実・危険・不足情報を分けて確認する
  ↓
複数の立場と案を作る
  ↓
同じ条件で比較する
  ↓
8つの判断材料へまとめる
```

## 1. 内容を整える

最初に、入力された文章の中心を確認します。

- 何を聞いているのか
- 何を達成したいのか
- 補足情報は何か
- 過去の回答が混ざっていないか

長い文章でも、中心となる問題と補足情報を分けて扱います。

## 2. 問題の分野を見つける

相談内容によって、確認すべきことは変わります。

たとえば、同じ「変更した方がよいか」という質問でも、対象が契約、健康、システム、採用、旅行では危険や比較条件が違います。

Asteraは、内容に合う分野を選び、その分野で必要な確認項目を加えます。

## 3. 3つの方向から同時に確認する

Asteraは、まず次の3方向から内容を見ます。

### 事実

- 入力の中で確認できる情報
- まだ確認できていない情報
- 意見や推測として扱うべき部分

### 危険

- 失敗した場合の影響
- 安全、費用、時間、運用上の問題
- 先に止めたり確認したりする条件

### 不足情報

- 判断するために足りない前提
- 対象、期限、予算、成功条件
- 利用者へ確認すべき質問

この3つを分けることで、「分かっているつもり」のまま結論へ進むことを減らします。

## 4. 複数の立場から考える

ひとつの案だけを強くすると、都合の悪い情報を見落としやすくなります。

Asteraは、次のような立場を使って内容を見直します。

- その案を進めたい立場
- 失敗を防ぎたい立場
- 前提そのものを疑う立場
- 対象分野に必要な立場

## 5. 主案以外の選択肢を作る

「やる・やらない」の二択だけではなく、次のような案も検討します。

- 条件を満たしてから進める
- 小さく試してから広げる
- 別の方法へ置き換える
- 一部だけ先に実行する
- 期限や対象を変える

これにより、現実的な第三案が見つかりやすくなります。

## 6. 同じ条件で比較する

複数の案を、別々の基準で評価すると正しく比べられません。

Asteraは、費用、時間、安全、効果、実行しやすさ、戻しやすさなど、問題に合う条件をそろえて比較します。

## 7. 8つの判断材料へまとめる

最後に、途中で見つかった内容を次の順番へまとめます。

| 番号 | 内容 |
|---:|---|
| 01 | 本当の目的 |
| 02 | 前提不足 |
| 03 | 事実確認 |
| 04 | 危機察知 |
| 05 | 反対視点 |
| 06 | 比較案 |
| 07 | 推奨判断 |
| 08 | 主役AIへの再指示 |

## Asteraと生成AIの違い

生成AIは、説明文、会話、要約、提案、コードなどを作ることが得意です。

Asteraは、その前に必要な判断材料を整理します。

```text
Astera ＝ 判断の骨組みを作る
生成AI ＝ 骨組みを使って最終回答を作る
```

どちらか一方を選ぶ関係ではありません。

Asteraが判断の見落としを減らし、主役AIが読みやすく実行しやすい回答へ仕上げます。

## 大切な考え方

Asteraの推奨は、絶対に従う命令ではありません。

新しい事実、利用者の希望、期限、予算、危険の大きさが変われば、推奨も変わります。

Asteraが目指すのは、結論を代わりに決めることではなく、**利用者が理由を理解した上で決められる状態を作ること**です。
