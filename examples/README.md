# 公開サンプル

このDirectoryでは、Asteraが入力をどのように8つの判断材料へ整理するかを、具体的な例で紹介します。

単に「入力と回答」を並べるのではなく、次の変化が分かるようにしています。

- 表面的な質問から、本当の目的がどう整理されるか
- 事実、未確認情報、推測がどう分かれるか
- 見落としていたRiskが何か
- 二択以外にどのような案が作られるか
- 推奨判断へどの条件が付くか
- 主役AIへ何を再指示するか

## Astera Appで試す流れ

1. [Astera App](https://app.asterav8.jp)の新しい実行を開く
2. サンプルの入力文をコピーする
3. サンプルに書かれた目的を選ぶ
4. 実行する
5. 公開サンプルと、自分のResultを比較する
6. 条件を一つ変更して再実行する

たとえば予約Systemの例では、次の条件を変えられます。

- Staff人数を5人から20人へ変える
- 移行期限を2か月から2週間へ変える
- Data移行を手作業へ変える
- 現行Systemの解約期限を追加する

条件が変わると、前提不足、Risk、推奨判断がどう変化するかを確認できます。

## サンプルの読み方

### 1. 先に入力だけを読む

Resultを見る前に、自分なら何を確認するか考えます。

### 2. 前提不足を読む

自分が見落としていた条件を確認します。

### 3. 事実確認を読む

入力に書かれた内容のうち、事実と断定できない部分を見ます。

### 4. 危機察知を読む

成功方法だけではなく、失敗、停止、Rollbackを確認します。

### 5. 比較案を読む

最初の二択以外に、段階案、対象限定、現行改善があるかを見ます。

### 6. 推奨判断を読む

おすすめの案だけでなく、その案が成立する条件を確認します。

### 7. 主役AIへの再指示を読む

判断材料を、計画書、確認表、手順、Codeなどへ仕上げる依頼を確認します。

## 公開サンプルと実際の利用の違い

公開サンプルは、初めて見る人が流れを理解しやすいように整理しています。

実際のAstera Appでは、次の情報もResultと一緒に扱います。

- 選択した目的
- 追加したFile
- 使用したTemplate・Option
- Turn
- Project
- History
- Result詳細
- コピー、Download、Share

詳しくは[Astera App完全ガイド](../docs/app-guide.md)と[Workspace・結果管理](../docs/workspace-and-results.md)をご覧ください。

---

## 大切な見方

Asteraの価値は、文章量や結論の強さではありません。

**結論を出す前に、見落としていた前提、事実と推測の混同、重大Risk、別の選択肢、停止条件が見えること**にあります。
